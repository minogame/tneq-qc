# example_custom_contract_strategy.py

This example demonstrates how to register and use a custom tensor contraction strategy. A mock strategy is implemented, registered, and selected by the contraction engine for tensor network contraction.

## Usage

```bash
python examples/example_custom_contract_strategy.py
```

## Outputs

After running, the console prints:

- The selected contraction strategy.
- The shape of the contraction result.
- The contraction result tensor.

No files are generated by this example.

## Notes

- The custom strategy is implemented by inheriting from `ContractionStrategy`.
- The example uses a mock strategy that delegates computation to the built-in einsum implementation.

# example_qctn_merge_split.py

This example demonstrates how to split a QCTN into multiple sub-networks using `chunk()` and reconstruct it with `concat()`. It also visualizes the adjacency matrices of the original, split, and merged tensor networks, and provides additional examples of concatenating different QCTN structures.

## Usage

```bash
python -m examples.example_qctn_merge_split
```

## Outputs

After running, the script:

- Prints the structures of the original, split, and merged QCTNs.
- Displays adjacency matrix visualizations for the original, split, and reconstructed tensor networks.
- Demonstrates concatenation of different QCTN structures (MPS, Tree, Wall, Circuit, and Mx).

No files are generated by this example.

# train_sample_quadratic.py

This example trains a Born Machine using negative log-likelihood (NLL) on samples generated from a target distribution defined by a quadratic form. After training, the model is evaluated by drawing samples and comparing the generated distribution with the target distribution.

## Usage

```bash
python -m examples.train_sample_quadratic
```

## Outputs

After training, the following files are generated:

- **Model checkpoint**
  - `checkpoints/born_machine_tn.safetensors`

- **Visualization**
  - `assets/born_machine/loss_curve.png`
  - `assets/born_machine/marginal_heatmap.png`
  - `assets/born_machine/samples_hist.png`
  - `assets/born_machine/samples_scatter_2d.png`

The console also reports the estimated KL divergence between the target distribution and the generated samples.

## Notes

- The target distribution is specified by a quadratic-form objective.
- The tensor network structure is defined by `GRAPH`.
- Training hyperparameters can be modified at the beginning of the script.

# train_mps_1024_correlated.py

This example trains a 1024-qubit MPS-based Born Machine on correlated Gaussian data using negative log-likelihood (NLL). After training, the model is saved and reloaded to verify the correctness of serialization.

## Usage

```bash
python examples/train_mps_1024_correlated.py
python -m examples.train_mps_1024_correlated
```

## Outputs

After training, the following files are generated:

- **Model checkpoint**
  - `checkpoints/mps_1024_correlated.safetensors`

The console also reports the training loss, initialization time, per-step runtime, and verifies that the saved model can be reloaded correctly.

## Notes

- Training samples are generated on-the-fly from a multivariate Gaussian distribution with nearest-neighbor correlation and are **not** stored on disk.
- The covariance matrix has unit diagonal entries and an off-diagonal correlation coefficient of **0.2** between adjacent variables.

# train_mps_brickwall_dist.py

This example performs distributed training of a custom MPS-of-Brickwall Born Machine using standard Gaussian data. It supports both single-process execution and multi-process training with `torchrun`, and reports training performance and memory usage for each process.

## Usage

```bash
# Single process
python examples/train_mps_brickwall_dist.py

# Multi-process
torchrun --nproc_per_node=2 examples/train_mps_brickwall_dist.py
torchrun --nproc_per_node=4 examples/train_mps_brickwall_dist.py
```

## Outputs

After training, the following files are generated:

- **Model checkpoint**
  - `checkpoints/mps_brickwall_dist.safetensors`

The console also reports the partition information, training loss, per-step runtime, peak memory usage for each process, and average training time.

## Notes

- The custom MPS-of-Brickwall graph is generated automatically based on `TOTAL_QUBITS`, `BLOCK_QUBITS`, and `OVERLAP`.
- Training samples are generated on-the-fly from a standard Gaussian distribution and are **not** stored on disk.
- Environment variables (`TOTAL_QUBITS`, `PHYS_DIM`, `BATCH_SIZE`, and `N_STEPS`) can be used to override the default training configuration.

# train_sliced_dist.py

This example demonstrates distributed Born Machine training using **cotengra's contraction slicing** through `EngineSliced`. Instead of partitioning the tensor network across processes, cotengra automatically decomposes the contraction into many independent slices, allowing different processes to evaluate separate slices in parallel and combine the results efficiently.

## Usage

```bash
# Single process
python examples/train_sliced_dist.py

# Multi-process
torchrun --nproc_per_node=2 examples/train_sliced_dist.py
```

## Outputs

No files are generated by this example.

The console reports the training loss and the number of contraction slices (`nslices`) generated by cotengra during optimization.

## Notes

- Install **cotengra** before running this example:

  ```bash
  pip install cotengra
  ```
- This example uses **cotengra's automatic contraction planner and slicing algorithm** to parallelize tensor contractions, rather than partitioning the tensor network itself.
- Every process stores the complete tensor network and evaluates a different subset of contraction slices. Partial results and gradients are synchronized by all-reduce.
- Training samples are generated on-the-fly from a standard Gaussian distribution and are **not** stored on disk.

# train_tneq.py

This example trains a small tensor network (student) to approximate a fixed tensor network (teacher) by maximizing the trace overlap between them. The student is optimized with an MSE loss on the traced contraction result, then saved and reloaded to verify serialization correctness.

## Usage

```bash
python examples/train_tneq.py
```

## Outputs

After training, the following files are generated:

- **Model checkpoint**
  - `checkpoints/tneq_student.safetensors`

The console also reports the training loss, the final trace overlap between the student and teacher networks, and verifies that the saved model can be reloaded correctly.

## Notes

- The teacher tensor network remains fixed throughout training, while only the student tensor network is optimized.
- The optimization objective is to make `Tr(student × teacher†)` approach **1.0**, corresponding to maximum overlap between the two tensor networks.
